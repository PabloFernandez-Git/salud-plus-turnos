El resultado «No pudimos preservar esta intención…» provenía de `persistIntentBeforeSubmit` cuando `sessionStorage.setItem` fallaba o el payload no superaba validación. Se reproduce localmente al bloquear `setItem`: no se llama a la acción y los campos permanecen en memoria. El texto ahora explica cómo reintentar sin desactivar la protección. Antes de confirmar no hay intención persistida: un refresh o navegación descarta el borrador y la contraseña. Después de un envío incierto, el mismo `operation_id` y payload no secreto permiten recuperar/reintentar sin doble alta; la contraseña debe reingresarse si aún se necesita. Cambiar email pide descarte explícito cuando hay datos editados. Back/Forward global sigue el comportamiento existente y no se amplió.

## Cambios UX
